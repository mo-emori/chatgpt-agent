# argus Structured Design Model Prompt v0.1.1

Design Source、ADR、Contract、Test Strategy を根拠として、argus の環境、課題、目的、要求・制約、機能、アクター、ロール、状態、データ、設定、処理、実現方式、外部主体、検証、成果物とその関係を内部入力として整理する。設計対象の知識と、文書を生成するための規則を混在させない。分析用の構造を Human System Design へそのまま露出させることを要求しない。根拠のない運用判断は Human Review として分離し、canonical source を変更しない。
