# Major Chapter 3 Human Structure Plan

## 読者の導線

読者が「何を満たせば起動できるか」から入り、通常運転の反復処理、異常終了を含む中断・再開、処理が守る正本とデータ種別、保存・復旧、最後に安全な配置へ進む時間順の導線とする。投資判断の意味や上位運用機能の詳細へ逸れず、実行基盤が受け持つ接続境界、Authority、失敗時挙動を追える構成にする。

## 子節の関係と説明順

1. 3.1 は起動責務を四つのSubsystemへ分離し、依存関係に従う実装順も示す。
2. 3.2 は起動後のJobを、Due判定から外部呼出し、Durable Stage、Atomic Commit、Projection、Retryまで一続きにする。
3. 3.3 は3.2の停止点をRunner状態機械と二種類のClockで説明し、復旧照合の詳細を3.5へ渡す。
4. 3.4 は前節までの処理対象を支える意味体系として、状態軸、Fact等の意味、正本と派生物、代表的なDomain状態機械を整理する。
5. 3.5 は3.4のAuthorityを崩さない保存、Backup、Restore後Reconciliation、Storage条件を示す。
6. 3.6 は停止、Backup、Code置換、Schema確認、再起動の順で、同じ安全境界をDeploymentにも適用する。

## 提案構造と詳細配置

- 各子節は責務・理由を先に置き、条件と処理、異常時挙動、禁止事項の順で読む構造にする。
- 3.1 の起動責務と実装段階、3.2 の周期Job、3.3 のClock用途、3.4 の分類・Artifact・Domain遷移、3.5 のArtifact・復旧・Storage、3.6 のConfig境界・配備手順は、対応関係を失わない表にする。
- 3.2 は外部副作用とLocal Commitの非対称性を含むためフロー図を置く。3.3 は正常終了とCrashを混同しないRunner状態図を置く。他節は表の方がAuthorityや条件を正確に表せるため図を増やさない。
- 具体値、状態名、identifier、path、禁止、例外、未確定主体は、それを適用する行の近くへ置く。

## 重複回避

起動順と実装順、実行フローとRunner状態、データ意味と保存場所、復旧とDeploymentを別の関心として分ける。3.2では復旧の入口だけを示して3.3・3.5を参照し、3.5ではデータ種別を再定義せず3.4のAuthorityを前提にする。投資判断・候補評価、Human approval、Risk、通知の内部仕様は再定義しない。
