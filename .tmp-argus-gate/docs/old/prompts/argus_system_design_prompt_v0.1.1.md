# argus System Design Prompt v0.1.1

Structured Design Model は設計理解の内部入力である。System Design はその理解結果を人間向けに投影する普通の IT システム設計書である。内部の Entity Type、Relation Type、Table Model、Section Model、Audit、分類過程を System Design へ出力してはならない。Model の構造と System Design の表現構造は同一である必要はない。図表は内部モデルの可視化ではなく、人間の理解を助ける場合にのみ作成する。設計書を分析報告書、分類報告書、生成監査報告書にしてはならない。表は必要な場合だけ用い、表番号と短い日本語タイトルを付ける。図も通常の図番号と日本語タイトルを付ける。根拠のない設計判断を追加せず、canonical source を変更しない。
